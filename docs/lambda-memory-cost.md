# Lambda 메모리/비용 가이드

이 문서는 크롤링 안정성과 비용 사이의 균형을 맞추기 위한 기준을 정리한다.

## 결론 (권장값)

- **Lambda 메모리: 4096 MB**
- **동시성: `concurrentPages = 2`**
- **배치 크기: 60 페이지 기준**

## 왜 4096 MB인가

- 로그 기준으로 2048 MB에서 **최대 사용량이 1.9GB 이상**까지 올라갔음.
- Chromium 크래시를 줄이려면 **메모리 여유가 필요**함.
- Lambda는 메모리 증설 시 **CPU도 함께 증가**해서 속도/안정성이 좋아짐.

## 비용 계산 개념

- Lambda 과금은 **GB‑sec(메모리 × 실행 시간)** 기반.
- 메모리를 2GB → 4GB로 올리면 **같은 시간 기준 비용은 2배**.
- 하지만 실행 시간이 줄면 비용이 일부 상쇄될 수 있음.

### 무료 티어 기준(요약)

- 월 **400,000 GB‑sec** 무료.
- 4GB 기준 무료 사용량 = **100,000초/월 (약 27.7시간)**.
- 호출량이 적고 실행 시간이 짧으면 **0원 유지 가능성 높음**.

## 50페이지 미만일 때

- 일반적으로 **메모리 초과 위험은 낮음**.
- 다만 페이지가 무겁거나 동시성이 높으면 급증 가능.
- 안정성 우선이면 4096 MB가 유리.

## 사용자가 해야 할 일

1) **Lambda 메모리 4096 MB로 변경**
   - AWS Console → Lambda → 해당 함수 → Configuration → Memory
2) **동시성/배치 값은 코드 반영 완료**
   - `concurrentPages = 2`
   - 배치 기준: 60 페이지
3) **적용 후 200페이지 테스트**로 안정성 확인
